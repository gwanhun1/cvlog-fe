# 프로젝트 구조·페이지·UI 정리

점검일: 2026-09-13. 프론트엔드 라우트, 컴포넌트 참조, 스타일 설정 및 백엔드 모듈을 읽은 정적 점검이다. 브라우저 렌더링, 로그인 후 동작, 사용량 분석은 수행하지 않았다. 아래 제품 구성은 제안이며 서비스 코드는 변경하지 않았다.

## 판단

핵심 기능은 개발 글 작성·탐색, GitHub 연동, 이력서 작성·공유다. 페이지를 대량 삭제하기보다 개인 관리 기능의 위치를 명확히 하고 반복 UI와 이전 구현을 정리하는 편이 적합하다. 코드에 존재하는 것과 실제 화면에 노출되는 것을 구분해야 한다.

## 현재 구조

- `cvlog-fe/`: Next.js 13 Pages Router. `pages/` 라우팅, `components/pages/` 도메인 UI, `components/Shared/` 공통 UI, `service/api/` API 계층.
- 비즈니스 훅은 `hooks/`와 `service/hooks/`로 분산되어 있다. 저장소 안내는 `hooks/use{Domain}.ts`를 권장하지만 기존 패턴은 혼재한다.
- 유틸리티는 `utils/`, `public/utils/`, `styles/utils/`에 분산된다. `public/`의 소스 유틸리티는 일반 소스 디렉터리로 옮길 후보이며 import 변경이 필요하다.
- `cvlog-be/`: NestJS. auth, users, posts, comments, likes, tags, tag_folders, notifications, resumes 및 entities 중심. 화면 정리만을 위해 백엔드 모듈이나 DB 테이블을 제거할 근거는 없다.
- FE와 BE는 별도 Git 저장소다.

## 페이지별 방향

| 경로 | 현재 역할 | 제안 |
| --- | --- | --- |
| `/` | 서비스 소개, 기능 영상, 글·GitHub·이력서 진입 | 유지하되 소개를 축소. 핵심 설명과 시작 버튼, 간단한 기능 소개 중심 |
| `/workspace` | 임시글, 이력서 목록, 백업 설정, 최근 기록 | 개인 작업의 중심으로 유지. 백업은 상태 요약과 설정 링크만 |
| `/article?view=all` | 공개 글, 대표 글, 인기 글, 주제·시리즈·검색·정렬 | 유지. 탐색 컨트롤을 한 영역으로 통합 |
| `/article?view=my` | 내 글 및 태그·폴더 관리 | 기능 유지. 작업실에서 명확히 진입하도록 구성 |
| `/article/liked` | 좋아요한 글 | 별도 상위 목적지보다 작업실 또는 내 글의 하위 탭 후보. 기존 URL 보존 |
| `/article/content/[pid]` | 공개/권한에 따른 글 읽기 | 유지 |
| `/article/new`, `/article/modify/[pid]` | 글 작성·수정 | 유지. 이미 공통 editor 컴포넌트가 있으므로 페이지 수가 중복의 근거는 아님 |
| `/resume` | 비회원 작성, 편집, 저장, 미리보기, 공유 | 유지. 화면과 저장 로직을 분리 |
| `/github` | GitHub 사용자·저장소 탐색, 기여도, 관련 글, 본인 백업 | 유지하되 탐색/활동과 백업 관리의 관계를 명확히 구성 |
| `/mypage` | 프로필, 연락처, 최근 활동, GitHub 설정, 계정 관리 | ‘계정 설정’으로 역할 축소. 최근 활동 제거, 백업 설정은 링크로 대체 |
| `/u/[username]` | 다른 사람이 보는 공개 프로필 | 유지. 개인 설정 페이지와 사용자가 다름 |
| `/r/[token]` | 링크로 공유한 이력서 | 유지. 작성 화면과 공유 화면은 목적이 다름 |
| `/login` | 로그인 | 유지 |
| `/join`, `/github/callback` | 인증 및 연동 콜백 | 유지. 일반 회원가입·콘텐츠 페이지가 아님 |
| `/404`, `/sitemap.xml`, `/rss.xml`, `/api/github/contributions` | 오류, 검색·구독, API | 일반 메뉴에서 보이지 않아도 필요한 인프라 경로 |

## 우선순위

예상 노력은 상대 크기다. 작음은 단일/소수 파일, 중간은 여러 화면과 회귀 확인, 큼은 상태·저장 로직 분리 수준이다.

| 순서 | 문제와 근거 | 정리 방향 | 기대 효과 | 노력 |
| --- | --- | --- | --- | --- |
| 1 | `Workspace.tsx`, `pages/mypage/index.tsx`, `GithubStudio.tsx`가 동일한 GitHub 백업 UI를 노출. `GithubSyncPanel.tsx`는 mypage의 `GithubSync` 재수출 | 실제 설정은 GitHub에 모으고 작업실에는 상태 요약, 계정 설정에는 링크 | 설정 위치 혼란과 화면 길이 감소 | 중간 |
| 2 | `RecentActivity`가 작업실과 마이페이지에 반복 | 작업실에 유지하고 마이페이지는 프로필·계정 설정 중심 | 개인 화면 역할 명확화 | 작음 |
| 3 | 공개 글 화면이 대표 글·인기 글·주제 카드·검색·내 글 탭·본문 목록으로 분산 | 검색·주제·정렬 통합. 대표/인기 영역은 축소 또는 접기 후보 | 본문 목록 접근성 개선 | 중간 |
| 4 | 홈의 히어로·3단계 카드·기능 영상·별도 이력서 CTA에서 기능 소개가 반복 | 주요 CTA와 간결한 기능 소개 유지. 영상은 필요할 때 열도록 검토 | 첫 방문자의 선택 부담 감소 | 중간 |
| 5 | 공통 Layout과 홈/작업실이 각각 폭·좌우 여백을 설정. `max-w-6xl`, `max-w-[1248px]`, container가 혼재 | 일반 페이지 폭·여백은 공통 셸에서 관리. 읽기·편집·인쇄는 목적에 맞는 별도 폭 | 페이지 이동 시 정렬 일관성 | 중간 |
| 6 | `ftBlue`와 blue/slate/gray 직접 지정, 공통 버튼과 개별 링크 버튼 스타일 혼재 | 색상·버튼 높이·모서리·제목 크기 기준 통일. 반복 영문 라벨과 카드 장식 축소 | 기능마다 다른 제품처럼 보이는 인상 완화 | 중간 |
| 7 | `/resume` 단일 파일이 1,796줄이며 입력 UI·정렬·저장·초안 처리 등이 함께 존재 | 페이지 진입점, 에디터 UI, 저장/초안 훅으로 분리 | 수정 영향 범위 및 회귀 위험 감소 | 큼 |

추가 관찰: `/login`에 이용약관·개인정보 처리방침 동의 문구가 있으나 해당 문구는 링크가 아니다. 실제 문서 연결 여부를 확인하고 접근 가능한 링크로 구성할 필요가 있다.

## 미사용 코드·정적 파일 후보

소스 검색에서 아래 GitHub 컴포넌트 이름은 정의 외 외부 사용처가 발견되지 않았다. 현재 `GithubStudio`는 `ContributionCalendar` → `GithubEChart` 경로를 사용한다.

- `components/pages/github/ProfileOverview.tsx`
- `components/pages/github/RepoHighlights.tsx`
- `components/pages/github/StatsSection.tsx`
- `components/pages/github/ActivityStats.tsx`
- `components/pages/github/ContributionChart.tsx`

이전 GitHub 통계 구현 잔재로 보이며 우선 제거 검토 대상이다. 실제 화면에 통계가 모두 중복 노출되고 있다는 뜻은 아니다. 삭제 전 동적 import·재수출까지 확인하고 타입 검사와 빌드로 검증한다.

아래 파일명도 저장소 텍스트 검색에서 참조가 발견되지 않았다.

- `styles/Home.module.css`: Next.js 초기 템플릿 형태의 스타일.
- `public/vercel.svg`
- `public/assets/logo-sample.png`
- `public/mockData/commentMockData.json`
- `public/mockData/contentMockData.json`

공개 정적 파일은 외부 URL 사용 가능성이 있어 내부 참조 부재만으로 삭제를 확정하지 않는다. `aboutMockData.json`은 홈 기능 데모가 실제로 import하므로 mockData 폴더 전체를 삭제하면 안 된다.

## 권장 정보 구조

- 비로그인 주요 메뉴: 글 탐색 / 이력서 / 로그인. 홈은 로고로 접근.
- 로그인 주요 메뉴: 작업실 / 글 탐색 / 이력서. GitHub는 제품에서 공개 탐색 기능을 얼마나 강조할지에 따라 주 메뉴 유지 또는 작업실 아래 배치.
- 작업실: 이어 쓰기 / 내 글 / 좋아요한 글 / 저장한 이력서 / GitHub 백업 상태.
- 계정 메뉴: 공개 프로필 보기 / 계정 설정 / 로그아웃.
- 계정 설정: 프로필 정보 / 연락처 / 계정 연동·관리.

## 진행 단계와 확인 기준

1. 참조가 없는 이전 컴포넌트·템플릿 파일 정리. 타입 검사 및 빌드 확인.
2. 마이페이지 최근 활동 및 여러 화면의 백업 설정 중복 정리. 로그인 상태별 링크와 비연동 계정 안내 확인.
3. 홈과 글 목록 UI 단순화. 검색·정렬·태그·시리즈·내 글 전환, 모바일/데스크톱 표시 확인.
4. 페이지 셸과 버튼·색상 기준 통일. 읽기 화면, 편집기, 공유 이력서 및 PDF 레이아웃 회귀 확인.
5. 이력서 로직·훅 구조 분리. 초안 복원, 계정 저장, 불러오기, 공유, PDF 출력 확인.

공개 프로필·공유 이력서·OAuth 콜백을 정리 과정에서 삭제하지 않는다. 개인 글과 백업 설정의 접근 권한은 UI 위치 변경 후에도 유지해야 한다.


## 구현 범위 (사용자 지시 반영)

글 리스트·글 상세·이력서 내부의 기능과 UI는 변경하지 않는다. 해당 화면의 공통 레이아웃, 관련 훅/API와 스타일도 이번 작업에서 유지한다. 기존 경로는 유지하고 작업실의 링크로 연결한다.

커밋은 다음 세 묶음으로 진행한다. 타입·린트·빌드는 모든 구현 후 한 번에 확인한다.

1. 개인 작업 공간 정리: 작업실을 초안과 최근 글 중심으로 변경하고, 계정 설정에서 중복 활동 UI 제거. `/workspace/github`에 기존 백업 설정을 모으고 작업실에는 상태 요약만 표시. 상단 메뉴에서 GitHub를 내리고 공개 프로필 진입점 추가.
2. 홈 간소화: 반복 소개와 CTA를 줄이고, 기능 영상은 사용자가 펼칠 때만 로드.
3. 사용하지 않는 이전 GitHub·마이페이지 컴포넌트 정리, 최종 검증 및 결과 기록.

이력서 직접 열기, 리스트 필터 통합, 상세 및 이력서 디자인 변경, 전역 스타일 통일은 이번 구현 범위에서 제외한다.
